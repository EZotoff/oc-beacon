## 大块整出回归排查 + 首跑/大放行限速（2026-09-27 下午批次·续）

### 用户报告
大 markdown 块（表格/有序无序列表）又整体一次性输出——之前「视觉换行就输出」的逐行感消失。

### 取证（~/card-lab/gran-probe.py，真机 houji 三轮）
- 反馈回路：v1(4199) CARD-EP11 会话 POST 表格 prompt → logcat MDPilot gate release/append 全量解析（分布/巨批/holding 占比）
- **app 放行链路无回归**：run1/2/3 共 240+ 条 release，p50=9-11ch、p90=41-44ch——表格区逐行放行正常（40-48ch/130ms/行）；holding（滚动暂缓）全程未触发（假设证伪）
- 「整块出」的真实来源（三层）：
  1. **中继缓冲突发（主因，上游）**：POST 后 22s 零 delta，随后 12s 内 900+ delta（~75 delta/s ≈ 500-800ch/s）——zhipuai 中继把回复缓冲后突发推送，到达节奏下逐行放行的行间隔仅 ~130ms，人眼即「整块」
  2. **多消息 turn 后续段全量到达**：turn 的第二条消息（无 delta 流，MessageUpdated 全量）首跑单帧 append 1136-2087ch（run2/run3 实证）
  3. **空行毕业段不受批预算约束**：SafePrefixGate 第一级 cand 直接放行——MAX_RELEASE_PER_BATCH 只管最后开放段，首跑/catch-up 单批可直达整段（append 1023ch 实证）

### 修复
1. **首跑多帧铺开**：pilot p==null 分支改循环（每批 gate 预算+帧间隔）——单帧巨量 append 消除
2. **#438① 大放行壁钟限速**：BIG_RELEASE_CH=200 / BIG_RELEASE_MIN_INTERVAL_MS=200——单批放行 ≥200ch 时两次大放行间隔 ≥200ms（与到达解耦；正常流式小批 p90=44ch 直通不受影响）——突发 catch-up 从「单帧砸出」变「快速分块出现」
3. **gate 单次放行上限**：SafePrefixGate.releaseLength/releaseDelta 加 maxReleaseChars 参数（默认无限兼容）——空行毕业段同样受批预算（截断点可落行中：released 坐标续放，lineStartReal 防御已覆盖行续段）；溢出坑（floor+Int.MAX_VALUE wrap）以先比较后相加排除
4. 测试：maxReleaseChars 截断/扣留语义优先 2 例 + 既有 37 例全绿

### 验证
- gran-run4（真机，含全部修复）：**append max 从 1023-2087 → 200**（BIG_RELEASE_CH 钳制生效）；turn 内两条巨量内容（1675ch 首跑+1173ch 后续段）均分批铺开（各 ~9/6 批 × ≥200ms）；p50=29ch 正常流式不受影响
- 中继突发（上游）不在 app 修复范围：用户若需更强「逐行感」可再调大 BIG_RELEASE_MIN_INTERVAL_MS（显示节流的产品参数）
