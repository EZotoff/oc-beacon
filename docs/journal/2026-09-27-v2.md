## #453 思考卡计时块级冻结 + 工具卡累积计时（f5103f80）

**用户报障**：思考卡片思考完毕之后，卡片自身的累积计时依然在增加；并要求排查其他卡片、让工具卡族具备累积计时能力。

### 根因（思考卡）

- 显示层计时走 `isReasoningStreaming = !partEnded && (hasValidAnchor || sessionStreaming)`；DSH 流式路径 `block-start` 给 start 锚、`block-end` **整帧 Ignored**（2026-09 裁决：mergePart isTerminal 覆盖语义下空文本终态 part 会清空流式文本）→ `time.end` 恒 null 直到 turn/end 的 markSessionIdle 兜底。
- 症状：思考块结束、正文块开始流式的整个窗口内 `partEnded=false + hasValidAnchor=true` → 计时持续虚涨，直到整个 turn 完结才冻结。V2 路径有显式 `session.reasoning.ended`（带 end）无此问题——bug 为 DSH 专属。

### 修复设计：MessagePartTimePatch（方案 K）

- block-end 帧无 blockType（黄金样本 mux-frames-extra #10），无法构造 kind 编码的派生 part id（PartIdContract）→ 双发 kind 猜测会创建空 part（依赖多层空过滤兜底，脆弱）。
- 新增域事件 `SseEvent.MessagePartTimePatch(sessionId, messageId, ordinal, endMs)`：消费端按 `_ord_{ordinal}` 后缀扫描定位（不分 kind），只补 `time.end == null` 的流式 Text/Reasoning（幂等——已终态块跳过，跨 kind 同 ordinal 历史块天然保护），Text start 缺失回填 endMs、Reasoning 保持 0 哨兵（#263 不伪造原则）。
- 链路：DshEventMapper.mapChunk block-end → DshConnectionOrchestrator dispatch → EventDispatcher registry（bind messageHandler）→ MessageEventHandler.handleMessagePartTimePatch（内存 + persistSseUpdate 落盘闭环，重启不回涨）。sealed 穷尽检查逼出 EventDispatcher.extractSessionId 分支补齐。

### 工具卡累积计时（新能力）

- **模型**：`ToolState.Pending` + `time: Time?`（Time(start)，默认 null 序列化向后兼容）——Running.Time/Completed.Time/Error.Time 原本就有。
- **映射填充**：DSH tool/call（Pending.time=start 信封）、tool/result（Completed/Error time start=0 哨兵 + end）、mapCodeDispatch Error 腿补 time；V2 tool.called（Running.time=start）、tool.success/failed（终态 time start=0 + end）。V1 服务器自带 state.time 不动。
- **mergePart Tool 分支 time 继承**（withInheritedStateTime）：incoming 无 time → 整体保留 existing 锚（REST 刷新/中间事件不清锚，防重进归零）；start<=0 哨兵 → 从 existing 补真实 start（跨度才真实）。REST 路径经 mergePartsList→mergePart 同覆盖。
- **显示层**：ToolCardScaffold 行尾固定槽 ToolElapsedText（数据判定非 isRunning 参数）：终态 duration>0 → 冻结静态；否则锚>0 → 100ms tick 走动（Pending 也算未完结——DSH tool/call 的 Pending 带锚即走动）；都无 → 不渲染（不伪造，思考卡 #263 同原则）。12 卡接线：ToolCardRenderer 通用 + Bash/Read/Edit/Glob/Search/Write/WebFetch/WebSearch/Task/ApplyPatch（tool.state）+ ShellCard（shell.time）。SkillCard/PatchCard/ContextToolGroupCard 等恒静态卡无计时语义不接。

### 教训

- 无状态映射器遇「后到的无 kind 完结信号」时，新增带 ordinal 的寻址型域事件优于消费端启发式或双发猜测。
